# 1. Сервер авторизации my_auth_server.py написан на FastAPI 
## 1.1. Установка зависимостей
```
pip install fastapi uvicorn pyjwt
```
1. `fastapi` — это сам веб-фреймворк (каркас приложения). Он берет на себя всю рутину работы с HTTP
2. `uvicorn` — это веб-сервер (ASGI-сервер), который открывает порт 8000, принимает сетевой трафик, передает его в приложение на FastAPI, а ответ отправляет обратно пользователю.
3. `pyjwt` — библиотека для работы с JWT (JSON Web Tokens). PyJWT берет данные пользователя (ID, права scope, время жизни), упаковывает их в JSON и подписывает секретным ключом (JWT_SECRET).
4. Установка шаблонизатора jinja:
```
pip install jinja2
```

## 1.2 Запустить сервер
```
uvicorn my_auth_server:app --host 0.0.0.0 --port 8000 --reload
```
## 1.2 Автоматическая документация Swagger
1. Перейдите в браузере по адресу http://localhost:8000/docs. Вы увидите интерактивный интерфейс для всех эндпоинтов. Внутри `FastAPI` уже встроена готовая веб-страница с графическим интерфейсом `Swagger UI`.
2. По адресу http://localhost:8000/openapi.json будет лежать готовая схема для фаззера `Schemathesis`. `FastAPI` собирает технический паспорт вашего API по международному стандарту OpenAPI и публикует его по адресу

Эти два адреса появляются полностью автоматически благодаря фреймворку `FastAPI`.

## 1.3 Запрос
Сделайте запрос на получение токена:
```
http://localhost:8000/authorize?response_type=code&client_id=admin&redirect_uri=http://localhost:8000/docs
```

# 2. Сервер авторизации auth_server.py написан на FastAPI и библиотекой Authlib
В продакшене используют либо готовые Identity Provider (например, Keycloak), либо проверенные криптографические библиотеки уровня Authlib.
## 2.1. Установка зависимостей
```
pip install fastapi uvicorn authlib sqlalchemy jinja2 python-multipart psycopg[binary]
```
## 2.2 Как запустить и проверить
1. Откройте терминал в корневой папке oauth.
2. Запустите сборку и старт одной командой:
```
docker compose up --build
```
3. Сначала стартует bank_auth_db, затем срабатывает healthcheck, и следом запускается bank_auth_server (running on http://0.0.0).
4. Откройте в браузере форму входа, чтобы убедиться, что всё работает:
```
http://localhost:8000/authorize?response_type=code&client_id=my_client_app&redirect_uri=http://localhost:8002/callback&scope=read
```
Связка «Сервер авторизации + База данных» готова и упакована в Docker.

## 3. Клиентское ПО
1. Запустите все 3 контейнера из корневой папки:
```
docker compose up --build
```
2. Откройте в браузере клиентское приложение: 
http://localhost:8002.

## 4. Запуск всей инфраструктуры
1. Откройте терминал в папке OAuth2.1/.
2. Запустите сборку и старт всех 4 контейнеров:
```
sudo docker compose up --build

sudo apt install docker-compose-v2
sudo docker compose up --build
```
3. Дождитесь, пока в логах появятся сообщения о запуске всех трех Python-сервисов на портах 8000, 8001 и 8002.
4. Получение JWT-токена. Откройте в браузере клиентское приложение: http://localhost:8002.
5. Нажмите «Войти через Банк ID (OAuth 2.1)».
6. На странице банка введите логин alice и пароль 123.
7. Вернет обратно на клиент, и на экране появится длинный Access Token (начинается на eyJ...). Скопируйте его.
8. Протестировать стенд можно двумя способами:

Способ А: Ручной взлом (Swagger UI в браузере)

9. Откройте интерактивную документацию Сервера ресурсов: http://localhost:8001/docs.
10. Нажмите на эндпоинт `GET /accounts/{target_user_id}` -> `Try it out`. 
11. В поле authorization вставьте: Bearer ВАШ_ТОКЕН_АЛИСЫ.
12. В поле target_user_id введите 99 (ID Боба) и нажмите Execute.
13. Результат (IDOR): Сервер покажет баланс Боба (5000.0), хотя вы вошли как Алиса (42).
14. Теперь откройте `POST /transfer` -> `Try it out`, вставьте токен и отправьте тело запроса:
```json
{
  "to_user_id": 99,
  "amount": -500
}
```
15. Результат (Отрицательный перевод): Баланс Алисы вырастет с 1000 до 1500 — вы украли деньги со счета Боба!

Способ Б: Автоматический фаззинг (Schemathesis)

16. Если хотите, чтобы робот сам нашел баги и гонки состояний без ручного перебора - установите фаззер:
```
pip install schemathesis
```
17. Запустите атаку на схему OpenAPI вашего сервера ресурсов (подставьте свой скопированный токен):
```
schemathesis run http://localhost:8001/openapi.json \
  --header "Authorization: Bearer ВАШ_ТОКЕН_АЛИСЫ" \
  --workers 5
```
18. Фаззер в 5 параллельных потоков начнет бомбить /transfer и /accounts отрицательными числами, нулями и одновременными списаниями. Как только баланс уйдет в минус, сработает наш assert sender.balance >= 0, сервер выдаст ошибку 500 Internal Server Error, и Schemathesis выведет в консоль точный curl-запрос, которым он сломал ваш банк.
19. Чтобы сбросить балансы в базе к исходным 1000 и 5000 руб., остановите контейнеры Ctrl+C и удалите том базы: docker compose down -v, после чего снова запустите docker compose up.

20. Остановить контейнеры и удалить старый том БД флагом -v:
```
sudo docker compose down -v
```

## 5. Запустить фаззинг по серверу ресурсов
1. Поднимите все контейнеры: 
```
docker compose up --build.
```
2. Получите свой JWT-токен через браузер (http://localhost:8002 -> Войти через Банк ID -> скопируйте длинный `Access Token` с экрана).
3. Установите фаззер локально:
```
pip install schemathesis
```
и запустите автоматический поиск логических багов одной командой, подставив скопированный токен:
```
schemathesis run http://localhost:8001/openapi.json \
  --header "Authorization: Bearer ВАШ_JWT_ТОКЕН" \
  --workers 5
```
Фаззер сам прочитает `/openapi.json` сервера ресурсов, найдет ручку POST `/transfer`, начнет подставлять туда -100.0, 0, 9999999 в 5 параллельных потоков и через несколько секунд выдаст вам готовый отчет о найденных уязвимостях!

## 6. Клиентское приложение: SPA (Single Page Application)
Данный сервис представляет собой чистый фронтенд-клиент (Public Client), реализованный по архитектуре SPA без серверного состояния (Backend-less). 
### Как работает: 
* Веб-сервер Nginx отдает браузеру пустую HTML-оболочку (index.html) и статический JavaScript-файл (app.js). Вся логика авторизации и отрисовки интерфейса выполняется на стороне браузера.
### Безопасность (OAuth 2.1 + PKCE):
  * Генерация code_verifier, code_challenge (SHA-256) и state реализована в браузере через стандартный Web Crypto API (window.crypto).
  * access_token хранится исключительно в оперативной памяти JS-переменной (не используется localStorage, чтобы снизить риск кражи при XSS).
  * На уровне Nginx настроены заголовки безопасности: Content-Security-Policy (CSP), X-Frame-Options и X-Content-Type-Options.

### Зависимости и требования
Для запуска и работы SPA не требуются Node.js, npm или внешние JS-фреймворки:
* Docker и Docker Compose (V2)
* Образ: nginx:alpine (устанавливается автоматически при сборке контейнера)
* Требования к бэкенду: на auth_server и resource_server должен быть настроен CORS для домена SPA (http://localhost:8002), а в списке разрешенных redirect_uri клиента должен быть добавлен http://localhost:8002/callback.

### Запуск
1. Перейдите в корневую директорию проекта (где расположен docker-compose.yml).
2. Соберите и запустите контейнер:
   ```bash
   sudo docker compose up -d --build
   ```
3. Откройте приложение в браузере:
   ```text

   ```
4. Остановить контейнеры:
   ```bash
   sudo docker compose down -v
   ```
